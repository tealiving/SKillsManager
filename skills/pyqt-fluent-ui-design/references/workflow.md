# UI 设计与主题工作流

## 1. 收集约束
- 明确页面范围、信息密度、交互状态（默认/悬停/禁用/错误）
- 确认平台与分辨率（Windows 为主、是否高 DPI）
- 确认品牌规范（主色、字体、圆角、动效偏好）

## 2. 建立 token 体系
- 先定义语义 token，再映射到主题色值
- 让 token 覆盖 90% 组件场景，避免每个控件单独配置

## 3. 主题模块化
- 每个主题一个模块，暴露相同接口（如 build_tokens）
- 主题模块只负责 token，不写控件逻辑

## 4. 主题注册与切换
- 建立 ThemeRegistry/ThemeManager
- 切换主题时只更新 token 与全局样式
- UI 通过事件/信号刷新，不直接读主题模块

## 5. 模块化样式输出
- 按“组件族”生成样式（如 buttons/cards/forms/navigation）
- 每个组件族只有一个入口函数，避免分散配置
- 仅在极少例外中对单个控件做 override，并说明原因

## 6. 验证清单
- Light/Dark 对比度：正文与背景至少可读
- 交互状态：hover/press/disabled 有清晰区分
- 一致性：同类控件间距、圆角、字号一致
- 可扩展：新增主题不需要修改组件样式逻辑
